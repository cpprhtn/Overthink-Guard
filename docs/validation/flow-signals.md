# 생각의 흐름으로 과잉 사고를 가려낼 수 있는가

- 작성: 2026-09-30, 특징을 계산하기 전에 방법과 합격 기준을 고정한다.
- 계기: 오너의 질문, "생각할 게 많은 질문은 생각을 많이 하는 게 맞다. 시간이나 토큰 수가 아니라 생각의 흐름을 추적해서 과잉 사고를 끊어야 하지 않나."
- 배경:
  - 기록된 정답 실행에서 thinking의 61%는 답이 이미 정답으로 굳은 뒤에 쓰였다. 규칙 D는 그중 16%만 잡는다(`docs/spikes/shadow-live-probe.md` 끝 절).
  - 규칙 D의 6,000토큰 조건은 늦은 수정(틀린 답을 오래 붙들다 검증 중에 고침)을 피하려고 붙인 길이 조건이다. 그 결과 규칙이 사실상 길이 상한이 됐다.
  - 이 연구는 길이 대신 흐름으로 "낭비성 재검증"과 "늦은 수정이 올 검증"을 가를 수 있는지 본다.
- 스크립트: `bench/spikes/flow_study.py`. 오프라인으로만 한다. 모델 호출이 없다.

## 데이터와 분할

생각 텍스트 전체(`segments`, 토큰 위치 포함)와 400토큰마다의 탐침 답이 있는 실행만 쓴다.

| 용도 | 파일 | 실행 |
| --- | --- | --- |
| 개발 (규칙을 만든다) | `shadow_third_qwen3`, `shadow_r1` | 80 |
| 검증 1 (한 번만 본다) | `shadow_fifth_qwen3`, `shadow_sixth_r1`, `math_d_qwen3`, `math_d_r1` | 130 |
| 검증 2 (오늘 밤) | `overnight_*` (`docs/validation/local-overnight.md`) | 수집되는 만큼 |

끊은 시점의 답은 그 시점의 탐침 답으로 대신한다(규칙 D 평가와 같은 대리값). 판정 정의(TP/FP/TN/FN)와 절감 계산은 `bench/spikes/probe_rule_matrix.py`와 같다.

## 흐름 특징 (탐침 시점 t마다, t까지의 생각만 사용)

창 W는 t 직전 800토큰의 생각 텍스트다.

| 특징 | 정의 | 뜻 |
| --- | --- | --- |
| streak | 가장 최근 탐침부터 연속으로 같은 답(정규화, grounded가 기록된 곳은 grounded만)의 개수 | 답이 굳었나 |
| novelty | W 안의 숫자 토큰 가운데 W 이전 생각에 한 번도 나오지 않은 것의 비율. 숫자가 없으면 0 | 새 계산을 하고 있나 |
| repeat | W의 단어 6-gram 가운데 W 이전에 이미 나온 것의 비율 | 같은 말을 되풀이하나 |
| doubt | W 안의 의심·수정 표현 수 (`wait`, `hmm`, `mistake`, `wrong`, `incorrect`, `actually`, `oops`, `contradict`, `re-examine`, `but no`) | 뭔가 이상하다고 느끼나 |
| verify | W 안의 검증 표현 수 (`check`, `verify`, `double-check`, `confirm`, `sanity`) | 검증 중인가 |
| restated | 현재 탐침 답이 W 텍스트에 나오는가 | 자기 답을 재확인하나 |

## 규칙 찾기 (개발 데이터에서만)

- **흐름 규칙 계열:** t ≥ T0이고, streak ≥ s, novelty ≤ n, doubt ≤ d, repeat ≥ r인 첫 탐침에서 끊는다.
  - 격자: s ∈ {2, 3}, n ∈ {0, 0.1, 0.2, 0.3, 1}, d ∈ {0, 1, 2, ∞}, r ∈ {0, 0.2, 0.4}, T0 ∈ {400, 1200, 2000}.
  - T0는 최소한의 시작점일 뿐이고, 2,000을 넘기지 않는다.
- **선택 규칙:** 개발 데이터에서 FP가 0인 규칙 중, 정상 종료 실행의 절감이 가장 큰 것을 고른다. 동점이면 더 보수적인 것(s가 크고, n과 d가 작은 것)을 고른다.
- **비교 기준선:** 같은 방식으로 "streak와 T0만 쓰는 규칙"(텍스트 특징 없음)도 고른다. 흐름 특징이 답 안정성 이상의 정보를 주는지 보기 위해서다.
- **최종 정책:** 흐름 규칙 OR 규칙 D. 규칙 D는 폭주를 막는 안전망으로 남긴다.

## 사전 등록한 합격 기준 (검증 1, 한 번만 계산)

| ID | 질문 | 합격 |
| --- | --- | --- |
| F1 | 정답을 지키는가 | 검증 1에서 FP ≤ 1 |
| F2 | 과잉 사고를 더 끊는가 | 정상 종료 실행의 절감 ≥ 20% (같은 데이터에서 규칙 D는 10%) |
| F3 | 폭주 방어가 나빠지지 않는가 | 끊지 못한 폭주(FN) 수가 규칙 D 이하 |
| F4 | 흐름이 답 안정성 이상을 주는가 (보고) | 흐름 규칙과 streak 기준선의 FP와 절감을 나란히 보고한다. 흐름 규칙이 FP를 늘리지 않으면서 절감이 5%p 이상 크면 "흐름 특징이 값을 한다" |

- F1–F3을 모두 넘으면 흐름 규칙을 Auto 신호 후보로 올린다. 다만 실제 "지금 답해" 경로로 생성한 답으로 한 번 더 실측해야 기본값이 된다(탐침 답은 대리값이다).
- 하나라도 넘지 못하면 그 결과를 그대로 적는다. 검증 데이터를 보고 규칙을 다시 고르지 않는다.
- 함께 보고:
  - 사후 기준(답이 정답으로 굳은 뒤의 thinking) 중 몇 %를 잡았는지
  - FP 사례의 흐름. 끊기 직전 창의 특징 값
  - 오늘 밤 데이터(검증 2)에서 같은 규칙의 결과
