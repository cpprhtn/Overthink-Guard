# 로컬 야간 검증: 규칙 D는 정답을 잃지 않는가

- 작성: 2026-09-30, 측정 전에 기준을 고정한다(concept D16).
- 배경: 혼동행렬 감사(`docs/spikes/shadow-live-probe.md` 끝 절)에서, 규칙 D의 "정답 손실 0"은 끊길 만큼 길었던 정답 실행 15개에서 나온 값이었다(95% 상한 약 20%). 또 12k 상한 때문에 가려진 손실 후보가 9개 있었고, 수렴 조건이 단순 길이 예산보다 낫다는 증거가 없었다.
- 목표: 정답을 최대한 지키면서 과잉 사고만 끊는다. 그래서 판정은 FP(끊어서 잃은 정답)를 중심으로 한다.

## 실행

```bash
ollama serve                                    # 이미 켜져 있으면 생략
python bench/spikes/overnight_local.py --hours 8
# 아침에
python bench/spikes/probe_rule_matrix.py --files bench/data/overnight_*.json --overnight
```

- 러너는 `otg start --probe`를 Shadow 모드로 띄운다. 아무것도 끊지 않고, 400토큰부터 400토큰마다 탐침 답을 기록만 한다. 그래서 어떤 규칙이든 나중에 오프라인으로 평가할 수 있다.
- 문제: OpenR1 held-out 160번 이후(두 모델 모두 처음 보는 문제). R1 풀이 평균 길이가 긴 것부터 푼다. 끊길 만큼 긴 정답 실행을 빨리 모으기 위해서다.
- 모델: `qwen3:1.7b`와 `deepseek-r1:1.5b`를 한 문제씩 번갈아 돌린다.
- 상한: `max_tokens` 24,000. 이전 12,000의 두 배로, 12k 상한 뒤에 가려졌던 결과를 보기 위해서다.
- 실행마다 바로 저장한다. 같은 명령을 다시 실행하면 이어서 돈다.
- 끊은 시점의 답으로는 기록된 탐침 답을 쓴다. 실제 Auto는 그 자리에서 답을 새로 생성하므로, 이것은 대리값이다.

## 사전 등록한 판정

규칙 D는 현재 기본값이다: k=4, 탐침 6,000토큰부터, grounded 답만 셈, 열린 질문 예산 10,000토큰. "적격"은 규칙이 발동할 수 있을 만큼(7,200토큰 이상) 길었던 정답 실행이다.

| ID | 질문 | 판정 |
| --- | --- | --- |
| B1 | 규칙 D가 정답을 잃는가 | 적격 100개 이상에서 FP 1개 이하면 합격(95% 상한 약 5%), 2개 이상이면 불합격. 적격이 100개 미만이면 합격/불합격을 말하지 않고 FP 수와 상한만 보고한다 |
| B2 | 수렴 조건이 값을 하는가 | 같은 실행에서 "7,200토큰에서 그때 탐침 답으로 끊기"(단순 예산)와 비교한다. 규칙 D의 FP가 **엄격히 적을 때만** 수렴 조건을 유지할 근거로 본다. 같으면 단순 예산이 더 간단하다는 결론이다 |
| B3 | 12k 상한이 손실을 가렸는가 | thinking이 12,000토큰을 넘었고 규칙 D가 멈춘 실행 가운데, 24k 안에 정답으로 끝났지만 멈춘 답은 틀렸던 비율. 이런 실행이 20개 이상일 때 5% 이하면 합격 |

- 결과를 보고 규칙이나 기본값을 새로 고르지 않는다. 판정 결과는 다음 결정의 근거로만 쓴다.
  - B1이 불합격이면 Auto 기본값을 보수적으로 바꾼다.
  - B2에서 차이가 없으면 탐침 없는 단순 예산을 검토한다.
- 함께 보고: 전체 혼동행렬, 절감률(전체, 정상 종료 실행만), FN(끊지 못한 폭주), 한 문제당 걸린 시간.
